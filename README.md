# 🌴 우리 가족 푸꾸옥 여행 웹앱 — 1차 프로토타입 (준비물 탭 직접 관리 v3)

**Python 실행이나 EXE 변환 없이**, HTML/CSS/JavaScript로 만들어진 모바일 웹앱입니다. PyCharm 또는 VS Code에서 수정할 수 있고, GitHub Pages에 게시하면 아이폰에서 링크로 접속할 수 있습니다.

> **중요:** 이번 버전은 **부부 전용 서비스를 준비하는 1차 시제품**입니다. **실제 로그인·부부 간 실시간 동기화는 아직 없습니다.** 데이터는 현재 사용 중인 브라우저에만 저장됩니다. GitHub Pages의 소스코드는 공개되므로 예약번호, 여권정보 등 실제 개인 정보를 소스 파일에 직접 입력하지 마세요.

## 1. 현재 가능한 기능

- **홈:** 여행 시작까지 D-Day, 선택 날짜의 일정, 해당 날짜에 유효한 예약정보, 남은 할 일
- **일정:** 날짜 선택, 일정 추가/수정/삭제, 시간·위치·링크·예약 연결
- **예약:** 항공권·호텔·교통·액티비티 예약정보, 예약번호·문서 링크·메모
- **장소:** 맛집·관광지·카페·해변 목록, 북부/중부/남부 분류, 찜, 구글지도 검색, 일정에 추가
- **준비물:** 출발 전 할 일·짐 챙기기·현지 확인 탭을 추가·이름 변경·삭제하고 화면 안에서 전환, 예약·서류·교통·아이들 짐 등 세부 분류, 담당자(나/아내/함께), 완료 체크, 관련 링크, 진행률, 미완료만 보기
- **설정:** 여행 날짜·제목 변경, JSON 백업 내보내기/불러오기, 링크 공유, 예시 데이터 초기화
- **아이폰:** Safari에서 열기, 홈 화면 추가, HTTPS 게시 후 기본 화면 파일 오프라인 캐시

첫 실행 시 **2026년 12월 27일~2027년 1월 2일**을 **임시 예시 날짜**로 사용합니다. 실제 여행 기간은 오른쪽 위 톱니바퀴 > **여행 설정**에서 수정하세요. 초기 일정 3개와 추천 준비 항목 41개는 편집 가능한 예시입니다. 실제 항공편·호텔 정보는 비어 있습니다.

## 2. 프로젝트 파일

```text
phuquoc-family-webapp/
├── index.html             # 앱 입구 / HTML 구조
├── styles.css             # 아이폰 최적화 디자인
├── app.js                 # 화면, 버튼, 입력 및 기능
├── data.js                # 최초 실행 시 표시할 예시 데이터
├── store.js               # 저장소 인터페이스 + 현재 localStorage
├── manifest.webmanifest   # 홈 화면 앱 이름/아이콘
├── sw.js                  # HTTPS 배포 시 기본 오프라인 캐시
├── assets/
│   ├── icon.svg
│   └── touch-icon.png
└── firebase/
    ├── README.md          # 후속 Firebase 연결 설계
    └── firestore.rules    # 후속 적용 참고용 보안 규칙 예시
```

## 3. PyCharm에서 실행하기

1. ZIP 파일을 압축 해제합니다.
2. **PyCharm > Open**에서 `phuquoc-family-webapp` 폴더를 엽니다.
3. PyCharm 터미널에서 다음 명령어를 실행합니다. (Python을 설치한 Mac이라면 대부분 바로 됩니다.)

```bash
python3 -m http.server 8000
```

4. Safari 또는 Chrome에서 **http://localhost:8000** 을 엽니다.
5. 코드를 수정하고 브라우저를 새로고침해 확인합니다.

HTML을 직접 더블클릭해도 열리는 브라우저가 있지만, 일부 브라우저는 `file://` 실행 시 브라우저 저장소를 제한할 수 있어 위 방식이 더 확실합니다.

### 주로 무엇을 수정하나요?

- **색·크기·레이아웃** → `styles.css`
- **메뉴, 버튼, 기능** → `app.js`
- **첫 실행용 예시 일정/준비물** → `data.js`
- **첫 화면의 HTML 뼈대** → `index.html`

`data.js`를 수정하더라도 기존 브라우저에 저장된 데이터가 남아 있으면 덮어써지지 않습니다. 새 예시 데이터를 적용하려면 앱의 설정 메뉴에서 **전체 초기화**하세요. (기존 입력 데이터는 삭제됩니다.)

## 4. GitHub Pages에 배포하기

1. GitHub 계정에서 새 **Public 저장소(repository)** 를 하나 만듭니다. 예: `phuquoc-trip`.
2. 이 ZIP을 풀어 **폴더 내부의 파일들(`index.html` 포함)** 을 저장소의 최상위(root)에 업로드합니다. 폴더 자체만 올려 `index.html`이 한 단계 깊이 들어가지 않게 주의하세요.
3. GitHub 저장소의 **Settings > Pages** 에서 배포 방식을 **Deploy from a branch**, 브랜치를 `main`, 폴더를 `/(root)`로 설정하고 저장합니다.
4. 배포된 주소(예: `https://사용자아이디.github.io/phuquoc-trip/`)로 접속합니다.
5. 아내분께 카톡으로 링크를 보내거나, 아이폰 Safari에서 열어 **공유 > 홈 화면에 추가**를 선택할 수 있습니다.

⚠️ **현재 링크를 공유해도 여행 데이터는 공유되지 않습니다.** GitHub Pages는 화면(HTML·CSS·JS)을 배포할 뿐이고, 데이터는 각각의 기기에 따로 저장됩니다. **실제 부부 전용 공동 편집**을 사용하려면 Firebase Authentication + Firestore를 연결해야 합니다.

GitHub Pages는 정적인 웹사이트를 공개적으로 배포하는 플랫폼입니다. 비공개 가족 정보, 예약번호, 공유 비밀번호, 민감한 API 키를 GitHub 저장소에 하드코딩하지 마세요. 특히 개인 정보가 든 `data.js`를 GitHub에 올리면 누구나 볼 수 있습니다.

## 5. 백업 · 기기 변경

톱니바퀴 > **백업 내보내기**를 누르면 JSON 파일이 저장됩니다. 다른 기기로 이동하려면 그 기기에서 같은 앱을 열고 **백업 불러오기**로 JSON 파일을 선택하세요. 이 방법은 **수동 복사**이고 부부 간 실시간 동기화는 아닙니다.

백업에는 등록한 예약번호와 링크, 메모가 포함될 수 있으므로 파일을 안전하게 보관하세요. 백업 파일을 불러오면 현재 브라우저 데이터가 **전체 교체**됩니다.

## 6. iPhone 관련 유의사항

- Safari에서 링크를 열고 **공유 > 홈 화면에 추가**하면 홈 화면 아이콘으로 실행할 수 있습니다.
- HTTPS로 배포했을 때 서비스 워커(`sw.js`)가 앱의 화면 파일을 오프라인 캐시합니다. **첫 온라인 접속 후**, 네트워크가 끊겨도 앱 화면과 현재 기기 데이터는 열 수 있습니다. 단, 외부 지도·예약 사이트 링크는 인터넷이 필요합니다.
- Safari 설정, 사생활 보호 모드, 브라우저 데이터 삭제, 저장 공간 부족 등의 상황에서는 데이터가 사라질 수 있으니 중요한 변경 후 백업하세요.
- 파일 수정 사항이 배포 후 화면에 늦게 반영되면 `sw.js`의 `CACHE_VERSION` 값을 다음 버전으로 변경해 배포하세요.

## 7. Firebase를 연결하려면

[`firebase/README.md`](firebase/README.md)를 참고하세요. 기존 화면과 데이터 스키마는 되도록 유지하고, `store.js`의 `LocalTripStore`를 인증 기반 `FirebaseTripStore`로 교체하는 방식으로 확장하도록 나누어 두었습니다. 공동 편집 시에는 전체 데이터를 하나의 문서로 덮어쓰지 않고, 일정/예약/장소/할 일을 **개별 Firestore 문서**로 다루는 것을 권장합니다.

## 8. v2 준비물 체크리스트 업데이트

- **준비물** 탭에서 **출발 전 할 일 / 짐 챙기기 / 현지에서** 3개 영역을 선택합니다. 각 영역의 소분류별로 항목을 확인하고 네모를 눌러 완료할 수 있습니다.
- 상단 **미완료만 보기**로 남은 항목만 볼 수 있고 **항목 추가**에서 나/아내/함께 담당을 지정하거나 링크·메모를 추가할 수 있습니다.
- 기존 v1에서 저장한 여행 데이터는 유지합니다. 새 버전 앱에서 준비물 탭의 **추천 체크리스트에 없는 항목 추가**를 눌러 새 목록을 기존 목록에 병합합니다. 이미 등록된 추천 ID는 중복 추가하지 않습니다.
- 코드를 수정해 새 기본 준비물을 넣더라도 기존 기기 데이터가 자동으로 사라지지 않습니다. **전체 초기화는 기존 사용자 데이터까지 지우므로** 주의하세요.
- 별도 Firebase 연결 전에는 여전히 **기기별 저장**이며, GitHub Pages 링크만 공유하면 체크 상태가 서로 동기화되지 않습니다.


## 9. v3 업데이트: 준비물 탭 자유롭게 관리

- **준비물 > 새 탭**을 눌러 원하는 이름의 탭을 추가합니다. 예: `아이들 준비물`, `출국 당일`, `구매할 것`.
- **준비물 > 탭 관리**에서 각 탭의 **이름 변경** 또는 **삭제**를 선택할 수 있습니다.
- 탭 삭제 시 그 탭에 포함된 준비물이 있으면 **다른 탭으로 항목 옮기고 삭제** 또는 **탭과 준비물을 모두 삭제**를 선택할 수 있습니다. 옮기는 경우 기존 체크 여부, 담당자, 메모, 링크는 보존되고 세부 분류는 `기타`로 전환됩니다. 모두 삭제를 선택하면 추가 확인이 표시됩니다.
- 마지막 탭은 삭제할 수 없고, 탭 이름은 중복될 수 없습니다. 새 탭에는 세부 분류 `기타`가 기본으로 적용됩니다.
- **기존 v1·v2 저장 데이터는 자동으로 새 탭 구조로 변환**됩니다. `store.js`의 localStorage 키는 이전과 같고, 기존 JSON 백업도 불러올 수 있습니다.
- GitHub Pages에 게시 중인 경우 ZIP 안의 파일을 덮어쓴 뒤 게시하고 다시 로드하세요. 오프라인 캐시는 `v3`으로 업데이트했습니다. 중요한 수정 전에는 앱 설정에서 JSON 백업을 보관하는 것을 권장합니다.
- 기존 탭을 삭제한 뒤 추천 체크리스트를 다시 추가하는 경우, **삭제된 탭에 속한 추천 항목은 건너뜁니다**. 탭 이름만 변경한 경우 추천 항목의 기존 그룹 연결은 유지됩니다.
